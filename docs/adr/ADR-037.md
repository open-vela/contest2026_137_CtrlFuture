# ADR-037: 加密加速器（SAES, HASH, RNG）

## Renode 模型说明

`tests/renode/peripherals/STM32N6_CRYP.cs` 是当前测试基础设施中的
加密加速器仿真模型（命名为 CRYP，覆盖 ADR 标题中的 SAES 部分）。
需要明确：CMSIS `stm32n647xx.h` 中既没有 `CRYP_TypeDef`/
`SAES_TypeDef`，也没有 `CRYP1_BASE`/`CRYP2_BASE`/`SAES_BASE` 等
基地址常量——只在 SYSCFG 防篡改复位掩码的注释里提到过 "SAES,
CRYP1/2, and HASH" 的名字，寄存器布局完全未公开（与之相对，同为
加密模块的 HASH 外设则有完整的 `HASH_TypeDef` 公开定义）。因此该
模型的 `CR@0x00/SR@0x04/DIN@0x08/DOUT@0x0C/KEYR0-3@0x10-0x1C/
IVR0-3@0x20-0x2C` 布局是团队参照通用 AES 协处理器惯例自定义的占位
设计，不能作为真实驱动的参考。未来实现真实 SAES 驱动时，必须以 ST
官方 HAL（`stm32n6_hal_saes.h`）或 DS14791 SAES 章节的专门寄存器
手册为准。

## 目标

> GitHub Issue: #42
> 验证级别: BUILD

实现 STM32N6 加密加速器驱动，
包括 SAES（AES）、HASH（SHA）、RNG（随机数生成器）。

## 上下文

STM32N647X0 有硬件加密引擎，特性：
- SAES: AES-128/192/256，ECB/CBC/CTR/GCM
- HASH: SHA-1/224/256/384/512，HMAC
- RNG: 真随机数发生器（TRNG）
- 硬件加速，比软件实现快 10-100 倍

DS14791 Section 15: SAES, Section 16: HASH, Section 17: RNG。
加密加速器用于安全通信、固件签名、密钥管理。

## 决策

**RNG + HASH 实现，SAES/CRYP 判定 N/A（硅片缺失）。**

- **RNG**: 真随机数发生器（TRNG）。驱动已有（`stm32n6_rng.c`，中断驱动 +
  FIPS 连续检验），本轮启用 `CONFIG_DEV_RANDOM`，由 NuttX 自动注册
  `/dev/random`；应用层 read() 获取真随机字节。
- **HASH (SHA-256)**: 提供 SHA-256 硬件加速。新增轮询式 arch 助手
  `stm32n6_sha256(input, len, digest)`，直接产出 32 字节摘要。SHA-256 是
  安全启动（ADR-038）固件度量的核心原语，优先实现；其余 SHA 变体与 HMAC
  框架化留待有实际调用方时再叠加。
- **SAES / CRYP（AES 加速器）**: **N/A**。核实 CMSIS 设备头
  `stm32n647xx.h` 后确认：`SAES_TypeDef` / `CRYP_TypeDef` 仅定义于
  `stm32n655xx.h` / `stm32n657xx.h`（带密码学加速器的 STM32N6 SKU）；本芯片
  N647X0 的头里既无寄存器结构体也无基址，SAES/CRYP 仅在 SYSCFG 防篡改复位
  掩码注释中被提及一次。即该外设在本硅片上**物理不存在**，非文档缺失，故
  不实现 AES 硬件驱动。需要 AES 时应走软件实现或换用带加速器的 SKU。

### 可测性（真机自证，无需示波器/接线）

RNG 与 HASH 都是纯片上外设，可在无外部仪器的真机上自证：
- **RNG**: 读两块随机数，断言非退化（非全零、非单字节重复）且两块互不相同，
  证明真实熵源在跑。
- **HASH**: 算 `SHA-256("abc")` 与 NIST FIPS 180-4 已知答案向量
  `ba7816bf...f20015ad` 逐字节比对，匹配即证明真实硬件计算——这是最强的
  已知答案证据，任何桩实现都无法伪造正确摘要。

## 设计

### 模块架构

```
加密加速器
├── SAES (AES 加密)
│   ├── AES-128/192/256
│   ├── 模式: ECB/CBC/CTR/GCM/CCM
│   ├── DMA 传输支持
│   └── 密钥寄存器 / OTP 密钥
│
├── HASH (哈希)
│   ├── SHA-1, SHA-224, SHA-256
│   ├── SHA-384, SHA-512
│   ├── HMAC
│   └── DMA 传输支持
│
└── RNG (随机数)
    ├── 真随机数 (TRNG)
    ├── 噪声源: 模拟振荡器
    └── 健康检测 (自检)
```

### NuttX 框架对接

```
NuttX crypto 框架:
  crypto_register("aes", &saes_ops)
  crypto_register("sha256", &hash_ops)
  /dev/hwrng (RNG 设备)

应用层 (加密):
  fd = open("/dev/crypto", O_RDWR)
  crypt_op op = { .op = COP_ENCRYPT, .cipher = "aes-cbc" };
  ioctl(fd, CIOCCRYPT, &op)

应用层 (随机数):
  fd = open("/dev/hwrng", O_RDONLY)
  read(fd, buf, 32)
  → 32 字节真随机数
```

### 数据流

```
AES 加密:
  明文 → SRAM
    → SAES DMA 读取 → AES 核心
    → 密文 → DMA → SRAM

SHA-256 计算:
  数据 → SRAM
    → HASH DMA 读取 → SHA 核心
    → 哈希值 (32B) → 寄存器

TLS 握手:
  RNG → 随机数生成
    → RSA/ECDH 密钥交换
    → AES-GCM 加密通道

## 理由

加密原语是安全通信与固件签名的基础设施。SHA-256 是安全启动（ADR-038）
固件度量的核心，优先实现并可用已知答案向量硬证明。TRNG 已有驱动，启用即可
真机自证。AES 硬件加速在本 SKU 上不可用（硅片缺失），需要时走软件实现。
