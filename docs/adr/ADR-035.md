# ADR-035: H.264 编码器

## Renode 模型说明

`tests/renode/peripherals/STM32N6_VENC.cs` 是当前测试基础设施中的
VENC 仿真模型。需要明确：CMSIS `stm32n647xx.h` 只公开了 `VENC_BASE`
基地址常量和一个被引用但从未定义的 `VENC_TypeDef` 类型名，**没有
公开任何寄存器偏移或位域定义**。因此该模型的 `CR@0x00/SR@0x04/
IER@0x08/CFG@0x0C/STRIDE@0x10` 布局是团队根据通用视频编码器 IP
惯例自定义的占位设计，不是 CMSIS 权威定义，也不能保证与真实硬件
一致。未来实现真实 `stm32n6_venc.c` 驱动时，必须以 ST 官方
`h264encapi`/HAL 文档或 DS14791 附带的寄存器手册为准，而不能参照
本模型的偏移布局。

## 上下文

STM32N647X0 有硬件 H.264 编码器（VENC），特性：
- H.264 Baseline/Main/High Profile
- 最高 1080p@30fps 编码
- 硬件运动估计和变换
- CBR/VBR 码率控制
- 依赖 DCMIPP（ADR-033）提供原始帧

DS14791 Section 42: VENC (Video Encoder)。
H.264 编码用于视频录制、实时传输、AI 视频分析。

## 决策

采用 ST VENC 库（h264encapi）的 Slice 编码模式，事件触发录制，输出至 SD 卡：

1. **编码库**: 使用 ST 提供的 `h264encapi` 接口（VENC 硬件编码器用户态库）
   - 非直接操作 VENC 寄存器，通过 ST 封装的 API 调用硬件编码器
   - 支持 Baseline Profile，满足嵌入式播放兼容性

2. **Slice 编码模式**:
   - 每帧拆分为多个 Slice 独立编码
   - 单个 Slice 输出缓冲区较小，降低 SRAM 峰值需求
   - 适合内存受限的嵌入式环境

3. **录制策略**:
   - 事件触发: 检测到目标（如人体姿态异常）时开始录制
   - 固定时长: 每段 30 秒 clip
   - 输出格式: 裸 H.264 NAL 流，写入 SD 卡（FatFS 文件系统）
   - 文件命名: 基于时间戳或事件序号

4. **输入源**: 从 DCMIPP 获取 YUV/RGB 帧数据，送入 VENC 编码

5. **码率控制**: CBR 模式，目标码率根据存储容量和录制时长计算

实现文件：
- `app/edgesight/recorder_hal.h` — 录制 HAL 接口定义
- `app/edgesight/recorder_hal.c` — h264encapi 封装、Slice 编码、FatFS 写入

## 设计

### 模块架构

```
VENC (H.264 编码器)
├── 编码模式
│   ├── I 帧 (关键帧)
│   ├── P 帧 (预测帧)
│   └── GOP 配置 (I/P 比例)
│
├── 输入
│   ├── YUV420 (NV12)
│   ├── YUV422
│   └── 来自 DCMIPP Pipe1
│
├── 输出
│   ├── H.264 NAL 单元
│   ├── 码率控制 (CBR/VBR)
│   └── DMA 输出到 SRAM
│
└── 控制
    ├── 分辨率/帧率设置
    ├── QP 值 (量化参数)
    └── 码率上限
```

### NuttX 框架对接

```
NuttX V4L2 编码器接口:
  video_register("/dev/video_enc0", &venc_dev)

应用层:
  fd = open("/dev/video_enc0", O_RDONLY)
  ioctl(fd, VIDIOC_S_FMT, &h264_fmt)
  ioctl(fd, VIDIOC_REQBUFS, &req)
  ioctl(fd, VIDIOC_STREAMON, 0)
  read(fd, &nal_buf, sizeof(nal_buf))
  → 返回 H.264 NAL 数据

视频流传输:
  DCMIPP → VENC → H.264 NAL
    → RTP 打包 → 网络传输 (ADR-022)
```

### 数据流

```
编码流程:
  DCMIPP Pipe1 → YUV420 帧
    → VENC 运动估计
    → 变换 + 量化
    → 熵编码 (CABAC/CAVLC)
    → NAL 单元 → DMA → SRAM
    → 应用 read()

## 理由

1. **h264encapi 封装层**: 直接操作 VENC 寄存器复杂度高且缺乏文档，ST 提供的 API 封装了硬件细节，开发效率更高。
2. **Slice 模式节省内存**: 全帧编码需要一次性分配完整帧的输出缓冲区，Slice 模式将输出拆分为小块，峰值内存占用降低数倍。
3. **事件触发而非连续录制**: 连续录制对 SD 卡写入带宽和存储容量要求高，事件触发只录制关键片段，实际存储需求可控。
4. **30 秒 clip 分段**: 避免单文件过大导致 FatFS 写入效率下降或断电丢失过多数据。
