# ADR-003: SysTick 系统节拍

## 状态

Accepted

## Phase

P0

## 目标

> GitHub Issue: #8
> 验证级别: BUILD

NuttX 调度器时钟源正常运行，`nxsched_process_timer()` 被周期调用。

## 上下文

NuttX 内核的 `clock_initialize()` 调用 `up_timer_initialize()`，
该函数必须由芯片驱动提供。Cortex-M55 内置 SysTick 定时器，
可作为系统节拍源。

PLL 尚未配置，SysTick 时钟源为 HSI 64MHz（处理器时钟）。

## 决策

使用 SysTick 定时器，时钟源选择处理器时钟（CLKSOURCE=1）。

重载值计算：`SYSTICK_RELOAD = (64000000 / CLK_TCK) - 1`

CLK_TCK 默认 100，重载值 639999，远小于 24-bit 上限 0x00ffffff。

## 设计

### 模块架构

SysTick 是 ARM Cortex-M 标准外设，集成在 CPU 核心内，
不在芯片外设总线上。它只有 4 个寄存器：

```
SysTick (NVIC 基地址偏移)
├── CTRL   (0x10) — 控制/状态
├── RELOAD (0x14) — 重载值 (24-bit)
├── CURRENT(0x18) — 当前计数值 (24-bit)
└── CALIB  (0x1C) — 校准值 (未使用)
```

### NuttX 框架对接

SysTick 在 NuttX 启动链中的位置：

```
nx_start()
  → clock_initialize()
    → up_timer_initialize()     ← 本 ADR 实现
      → irq_attach(SYSTICK)     ← 注册中断处理
      → 配置 CTRL 寄存器        ← 使能定时器+中断
      → up_enable_irq(SYSTICK)  ← NVIC 使能 SysTick 异常

每个 tick 中断:
  SysTick_Handler
    → stm32n6_timerisr()
      → nxsched_process_timer() ← NuttX 调度器处理
        → 更新时间片、检查超时、唤醒睡眠任务
```

关键：`up_timer_initialize()` 在 `__start()` → `nx_start()` 调用链中
被调用，此时中断尚未全局使能（`up_irq_enable()` 在 `up_irqinitialize()`
末尾调用）。所以 SysTick 配置不会被中断打断。

### 数据流

```
HSI 64MHz (处理器时钟)
  │
  ├─ CLKSOURCE=1 → SysTick 直接使用处理器时钟
  │
  └─ RELOAD = 64000000/100 - 1 = 639999
       │
       └─ 每 640000 个时钟周期 (10ms) 触发一次中断
            │
            └─ stm32n6_timerisr()
                 └─ nxsched_process_timer()
                      ├─ 更新系统时间 (g_system_ticks++)
                      ├─ 检查时间片轮转
                      ├─ 检查 sleep/timeout 唤醒
                      └─ 触发上下文切换 (如需要)
```

## 实现说明

### 关键寄存器配置

**NVIC_SYSTICK_CTRL (0xE000E010)**：
- bit 2 `CLKSOURCE` = 1：选择处理器时钟（HSI 64MHz）
  - 若 = 0 则使用外部参考时钟（STM32N6 上未配置）
- bit 1 `TICKINT` = 1：使能中断请求
- bit 0 `ENABLE` = 1：启动计数器
- 三个位同时写入：`0x07`

**NVIC_SYSTICK_RELOAD (0xE000E014)**：
- 24-bit 寄存器，最大值 0x00FFFFFF (16777215)
- 64MHz / 100Hz = 640000 个周期，639999 < 16777215，安全
- 编译期校验：`#if SYSTICK_RELOAD > 0x00ffffff` → `#error`

**NVIC_SYSTICK_CURRENT (0xE000E018)**：
- 写任意值清零计数器（写时清除特性）
- 初始化时写 0 确保从 RELOAD 值开始计数

### 代码模式

**编译期安全校验**：
```c
#if SYSTICK_RELOAD > 0x00ffffff
#  error SYSTICK_RELOAD exceeds the range of the RELOAD register
#endif
```
这是嵌入式开发的常见模式：用 `#if` + `#error` 在编译期捕获
参数越界，而非运行时崩溃。24-bit RELOAD 寄存器在修改 CLK_TCK
或时钟频率时容易溢出，这个检查能立即发现问题。

**中断注册**：使用 `irq_attach()` 而非直接写向量表。
`irq_attach()` 是 NuttX 的标准 API，它：
1. 在 RAM 向量表中注册处理函数
2. 支持运行时更换中断处理函数
3. 与 NuttX 的中断统计/追踪功能集成

### 踩坑与解决

1. **CLK_TCK 配置位置**：`CLK_TCK` 默认值 100 定义在
   `nuttx/include/nuttx/clock.h` 中，可通过 Kconfig
   `CONFIG_USEC_PER_TICK` 修改。当前 nsh defconfig 未设置
   `CONFIG_USEC_PER_TICK`，使用默认值 10000（即 CLK_TCK=100）。
   如果后续需要更高精度定时（如 1000Hz），需修改 defconfig
   并重新计算 SYSTICK_RELOAD 确保不超 24-bit。

2. **SysTick 与 PLL 的关系**：当前 HSI 64MHz 直连，
   SysTick 频率精确。ADR-005 配置 PLL 后 CPU 时钟频率变化，
   SysTick 会自动跟随（因为它用处理器时钟），
   但 `board.h` 中的 `STM32_HSI_FREQUENCY` 需要更新为
   新的 CPU 时钟频率，否则 SYSTICK_RELOAD 计算错误。

## 理由

SysTick 是 ARM Cortex-M 标准外设，无需额外时钟配置。
替代方案（TIM2 等通用定时器）增加 RCC 依赖和代码量，
在 PLL 配置前没有优势。

选择 HSI 64MHz 作为时钟源而非外部参考时钟：
- DEV boot 模式下 HSI 已就绪
- 精度足够满足系统节拍需求
