# ADR-003: SysTick 系统节拍

## 状态

Accepted

## Phase

P0

## 目标

> GitHub Issue: #8
> 验证级别: BUILD

NuttX 调度器时钟源正常运行，`nxsched_process_timer()` 被周期调用。

## 上下文

NuttX 内核的 `clock_initialize()` 调用 `up_timer_initialize()`，
该函数必须由芯片驱动提供。Cortex-M55 内置 SysTick 定时器，
可作为系统节拍源。

PLL 尚未配置，SysTick 时钟源为 HSI 64MHz（处理器时钟）。

## 决策

使用 SysTick 定时器，时钟源选择处理器时钟（CLKSOURCE=1）。

重载值计算：`SYSTICK_RELOAD = (64000000 / CLK_TCK) - 1`

CLK_TCK 默认 100，重载值 639999，远小于 24-bit 上限 0x00ffffff。

## 理由

SysTick 是 ARM Cortex-M 标准外设，无需额外时钟配置。
替代方案（TIM2 等通用定时器）增加 RCC 依赖和代码量，
在 PLL 配置前没有优势。

选择 HSI 64MHz 作为时钟源而非外部参考时钟：
- DEV boot 模式下 HSI 已就绪
- 精度足够满足系统节拍需求
