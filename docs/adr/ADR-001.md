# ADR-001: CI 集成（symlink + Kconfig patch）

## 状态

Accepted

## Phase

P0

## 目标

> GitHub Issue: #6
> 验证级别: BUILD

NuttX CI 构建系统能编译 STM32N6 芯片驱动，无需上游合入。

## 上下文

openvela/NuttX 的 arch 层代码位于 `nuttx/arch/arm/src/<chip>/`，由
NuttX 内核 Kconfig 和 Makefile 系统引用。比赛仓库不能直接修改 NuttX
源码树，需要在 CI 和本地开发时通过 symlink + Kconfig patch 将本仓库
的芯片驱动注入到 NuttX 构建系统中。

## 决策

使用三步注入方案：

1. symlink `arch/arm/stm32n6/src` → `nuttx/arch/arm/src/stm32n6`
2. symlink `arch/arm/stm32n6/include` → `nuttx/arch/arm/include/stm32n6`
3. `git apply` Kconfig patch 向 `nuttx/arch/arm/src/Kconfig`
   注入 `source "arch/arm/src/stm32n6/Kconfig"`

## 实施步骤

1. [x] 创建 `arch/arm/stm32n6/kconfig-stm32n6.patch`
2. [x] 在 `.github/workflows/build.yml` 中添加 symlink 和 patch 步骤
3. [x] 验证 nsh 和 nsh-qemu 双目标编译通过

## 验证标准

- [x] `ci-check.sh` 编译通过（BUILD）
- [x] GitHub Actions nsh + nsh-qemu 双目标绿灯
- [x] 本地 symlink 后 `build.sh` 编译通过

## 理由

symlink + patch 方案是 NuttX 社区推荐的 out-of-tree 开发方式，不侵入
NuttX 内核代码，且 CI 可完全自动化。替代方案（git submodule 或直接
fork NuttX）会增加维护成本和合入冲突。
