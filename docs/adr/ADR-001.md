# ADR-001: CI 集成（symlink + Kconfig patch）

## 状态

Accepted

## Phase

P0

## 目标

> GitHub Issue: #6
> 验证级别: BUILD

NuttX CI 构建系统能编译 STM32N6 芯片驱动，无需上游合入。

## 上下文

openvela/NuttX 的 arch 层代码位于 `nuttx/arch/arm/src/<chip>/`，由
NuttX 内核 Kconfig 和 Makefile 系统引用。比赛仓库不能直接修改 NuttX
源码树，需要在 CI 和本地开发时通过 symlink + Kconfig patch 将本仓库
的芯片驱动注入到 NuttX 构建系统中。

## 决策

使用三步注入方案：

1. symlink `arch/arm/stm32n6/src` → `nuttx/arch/arm/src/stm32n6`
2. symlink `arch/arm/stm32n6/include` → `nuttx/arch/arm/include/stm32n6`
3. `git apply` Kconfig patch 向 `nuttx/arch/arm/src/Kconfig`
   注入 `source "arch/arm/src/stm32n6/Kconfig"`

## 设计

### 模块架构

注入分为三层，每层解决一个独立问题：

```
contest2026_137_CtrlFuture/          nuttx/
├── arch/arm/stm32n6/                ├── arch/arm/src/stm32n6/  ← symlink (src)
│   ├── src/                         ├── arch/arm/include/stm32n6/ ← symlink (include)
│   └── include/                     └── arch/arm/src/Kconfig   ← patch 注入 source
├── arch/arm/stm32n6/kconfig-stm32n6.patch
└── .github/workflows/build.yml      ← CI 自动化
```

Kconfig patch 在 `nuttx/arch/arm/src/Kconfig` 中插入 9 行：
- 定义 `config ARCH_CHIP_STM32N6`（select CORTEXM55/MPU/FPU/MVE）
- 设置 `ARCH_CHIP` default 为 `"stm32n6"`
- 在 `if ARCH_CHIP_STM32N6` 块中 source 芯片 Kconfig

### NuttX 框架对接

NuttX 构建系统通过两个机制发现芯片驱动：
1. **Kconfig**: `if ARCH_CHIP_STM32N6` → `source "arch/arm/src/stm32n6/Kconfig"`
   使 `menuconfig` 能看到 STM32N6 选项
2. **Makefile**: `arch/arm/src/Makefile` 根据 `CONFIG_ARCH_CHIP` 值
   include 对应芯片目录的 `Make.defs`

symlink 让这两个机制无需修改 NuttX 源码即可工作。

### 数据流

```
repo sync (NuttX + apps)
  → checkout PR code (本仓库)
  → ln -s ../../../../contest.../src  nuttx/arch/arm/src/stm32n6     (相对路径)
  → ln -s ../../../../contest.../include  nuttx/arch/arm/include/stm32n6
  → git apply kconfig-stm32n6.patch
  → build.sh → Makefile include stm32n6/Make.defs → 编译 .c 文件
```

## 实现说明

### 关键寄存器配置

本 ADR 不涉及寄存器操作。Kconfig patch 的关键选择：
- `select ARCH_CORTEXM55` — 告诉 NuttX 使用 ARMv8-M Cortex-M55 支持
- `select ARCH_HAVE_MPU` / `ARCH_HAVE_FPU` / `ARM_HAVE_MVE` —
  声明芯片硬件能力，使 NuttX 编译对应的 MPU/FPU/MVE 代码

### 代码模式

**symlink 使用相对路径**：`../../../../contest2026_137_CtrlFuture/arch/arm/stm32n6/src`
而非绝对路径。原因：Docker 容器内的工作目录与宿主机不同，
绝对路径 `/home/takumi/...` 在容器内不存在。
相对路径从 `nuttx/arch/arm/src/` 出发，向上 4 层到达 workspace root，
再进入本仓库目录。这保证了本地开发和 CI Docker 环境都能工作。

### 踩坑与解决

1. **绝对路径在 Docker 中断裂**：最初使用绝对路径 symlink，
   CI Docker 环境中 workspace 挂载路径不同导致断裂。
   改为相对路径后解决（commit `7b9815a`）。

2. **Kconfig patch 位置敏感**：patch 需要在正确的 `if` 块内插入，
   上游 NuttX 的 Kconfig 行号可能变化。使用 `git apply` 而非
   `patch -p1`，git 会尝试 fuzzy match。

## 验证标准

- [x] `ci-check.sh` 编译通过（BUILD）
- [x] GitHub Actions nsh + nsh-qemu 双目标绿灯
- [x] 本地 symlink 后 `build.sh` 编译通过

## 理由

symlink + patch 方案是 NuttX 社区推荐的 out-of-tree 开发方式，不侵入
NuttX 内核代码，且 CI 可完全自动化。替代方案（git submodule 或直接
fork NuttX）会增加维护成本和合入冲突。
