# ADR-008: TCM 配置（DTCM + ITCM）

## 状态

Done

## Phase

P1

## 目标

> GitHub Issue: #13
> 验证级别: MEASURED

配置 Cortex-M55 的紧耦合存储器（TCM），
将关键代码/数据放入 ITCM/DTCM 以获得零等待周期访问。

## 上下文

Cortex-M55 提供：
- ITCM：指令紧耦合存储器，零等待周期取指
- DTCM：数据紧耦合存储器，零等待周期读写

DS14791 Section 3.2: TCM 接口。
STM32N6 的 TCM 大小需查 datasheet 确认。
TCM 适合存放中断处理函数、关键数据结构（如调度器队列）。

## 决策

STM32N647X0 TCM 规格（来自 DS14791）：
- ITCM: 64 KB @ 0x00000000，带 ECC
- DTCM: 128 KB @ 0x20000000，带 ECC

分配策略：
1. **ITCM (64KB)**: 存放中断向量表 + SysTick ISR + 调度器热路径
2. **DTCM (128KB)**: 存放 idle 栈 + 调度器关键数据结构 + NPU 推理控制结构
3. **不用 TCM 做堆**: TCM 空间有限，仅放静态分配的关键数据

链接脚本添加：
```ld
MEMORY
{
  itcm (rx)  : ORIGIN = 0x00000000, LENGTH = 64K
  dtcm (rw)  : ORIGIN = 0x20000000, LENGTH = 128K
  sram (rwx) : ORIGIN = 0x34000400, LENGTH = 4192K
}

SECTIONS
{
  .itcm : { *(.vectors) *(.itcm*) } > itcm
  .dtcm : { *(.dtcm*) } > dtcm
}
```

注意：DEV boot 模式下，固件加载到 SRAM 执行，需在 `__start()` 中
将 .itcm/.dtcm 段从 SRAM 拷贝到 TCM（类似 .data 段初始化）。

## 设计

### 模块架构

```
内存层次结构:
┌─────────────┐  零等待周期
│    ITCM      │  ← 中断向量表 + ISR
├─────────────┤  零等待周期
│    DTCM      │  ← 关键数据 + 栈
├─────────────┤  1-2 等待周期 (有缓存)
│  SRAM (AXI)  │  ← 代码 + 堆 + 大数据
├─────────────┤  较高延迟
│  外部 Flash  │  ← ADR-019 XSPI 启动
└─────────────┘

链接脚本扩展:
  .itcm : { *(.itcm*) }  > ITCM
  .dtcm : { *(.dtcm*) }  > DTCM
```

### NuttX 框架对接

```
NuttX 内存区域:
  up_allocate_heap() → SRAM 堆 (已有)
  → 可选: DTCM 分配为独立堆

GCC 属性标记:
  __attribute__((section(".itcm"))) void isr_handler(void);
  __attribute__((section(".dtcm"))) volatile uint32_t critical_data;
```

## 理由

ITCM/DTCM 提供零等待周期访问，在 800MHz 主频下效果显著。
中断向量表放 ITCM 可消除中断响应的取指延迟。
DTCM 的 128KB 足够放调度器数据和少量关键缓冲区。
不将 TCM 用作通用堆，避免碎片化影响关键路径。
