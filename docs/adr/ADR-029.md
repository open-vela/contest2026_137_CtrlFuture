# ADR-029: ADC 驱动

## 状态

Partially Accepted — 内部通道单次查询 (ADC1 /dev/adc0, VREFINT 通道 17)
已实现并真机 MEASURED（drivertest_adc PASS）；外部通道/多通道扫描/DMA/
模拟看门狗作为独立子项待实现。

## Phase

P4

## 目标

> GitHub Issue: #34
> 验证级别: MEASURED

实现 STM32N6 ADC 驱动，支持多通道模拟信号采集，
用于传感器读取、电压检测、电池电量监测等。

## 上下文

STM32N647X0 有 ADC1/ADC2，特性：
- 12-bit SAR ADC，最高 16.5Msps
- 多路复用输入通道
- 支持 DMA 传输
- 注入通道（高优先级）+ 规则通道
- 模拟看门狗（阈值检测）

DS14791 Section 23: ADC。
ADC 是连接模拟世界和数字世界的桥梁。

## 决策

实现 ADC1 单次查询（软件触发 + 轮询）下半层，采集芯片内部电压参考
VREFINT（通道 17），对接 NuttX ADC 字符设备框架（/dev/adc0）。选择
内部通道是因为它无需外部布线，可在任意板子上直接跑真机 drivertest。

不实现（作为独立子项延后）：外部模拟输入通道、多通道扫描、DMA、
连续转换、注入通道、模拟看门狗。EdgeSight 无外部模拟传感器接入需求，
这些子项投入产出比低，按需评估。

### STM32N6 与 STM32H7 的关键差异

移植 stm32h7 参考实现时踩到三处芯片差异，均已在真机验证中定位：

1. **无 ADVREGEN 位** — N6 清除 CR.DEEPPWD 即使能 ADC 电压调节器
   （需 ~10µs 稳定），不存在 H7 的独立 ADVREGEN 位。
2. **无盲校准** — H7 的 "ADEN=0 时置 ADCAL 等待自清零" 流程在 N6 上
   永不清零（N6 用 ADC 使能后的平均偏移测量校准）。校准仅修正静态
   偏移，对读 VREFINT 无意义，故完全跳过。
3. **VDDA 模拟供电开关** — 必须置 PWR.SVMCR3.ASV（bit 12，等价于
   HAL_PWREx_EnableVddA），否则转换照常完成、EOC 照常置位，但数据
   寄存器恒读回 0。此位缺失是真机 raw=0 的根因（经 ST ALIENTEK N647
   BSP adc.c 交叉验证确认）。

此外 N6 上电后可能过早清除 ADEN，故 ADEN 置位后需轮询 ADRDY 期间
反复重写 ADEN 直至就绪。

## 设计

### 模块架构

```
ADC1/ADC2
├── 转换模式
│   ├── 单次转换 (Single)
│   ├── 连续转换 (Continuous)
│   ├── 扫描模式 (Scan, 多通道)
│   └── 注入模式 (Injected, 高优先级)
│
├── 通道配置
│   ├── 规则通道 (Regular, CH0-CH19)
│   ├── 注入通道 (Injected)
│   ├── 采样时间可编程
│   └── 模拟看门狗 (阈值比较)
│
└── 触发源
    ├── 软件触发
    ├── 定时器触发 (TIM1/TIM8 TRGO)
    └── 外部中断触发
```

### NuttX 框架对接

```
NuttX ADC 框架:
  adc_register("/dev/adc0", &adc_dev)

应用层:
  fd = open("/dev/adc0", O_RDONLY)
  read(fd, &adc_msg, sizeof(adc_msg))
  → 返回多通道采样值

DMA 模式:
  定时器触发 → ADC 扫描 → DMA 传输
    → 环形缓冲区 → 应用读取
```

### 数据流

```
单通道查询:
  应用 → read()
    → ADC 软件触发
    → SAR 转换 → DR 寄存器
    → 返回 12-bit 值

多通道 DMA:
  TIM 触发 → ADC 扫描 CH0-CHn
    → DMA → 内存环形缓冲区
    → 中断通知 → 应用 read()

## 实施步骤

1. [x] 实现 ADC 上电时序（使能 AHB1 时钟 → 置 VDDA.ASV → 清 DEEPPWD
   使能调节器 → 使能 ADEN 轮询 ADRDY），跳过盲校准
2. [x] 实现单通道单次查询（VREFINT 通道 17：CCR.VREFEN 路由 + PCSEL
   预选 + SMPR 最长采样时间 + SQR1 单元素序列）
3. [x] 实现软件触发 + 轮询 EOC（ANIOC_TRIGGER → ADSTART → 轮询 →
   读 DR → 上半层 au_receive），所有轮询带超时（-ETIMEDOUT）
4. [x] 集成 NuttX ADC 框架（adc_register /dev/adc0）
5. [x] 编译验证（ci-check 双目标 + renode 回归）
6. [ ] 外部通道 / 多通道扫描 / DMA / 模拟看门狗（独立子项待实现）

## 验证标准

- [x] `ci-check.sh` 编译通过（BUILD）
- [x] ADC 单通道采样值正确（drivertest_adc 真机 PASS，MEASURED：
  VREFINT 读回 ~1912 LSB 并有 ±2 LSB 真实转换抖动，证明是活转换
  而非常量桩）
- [ ] 多通道 DMA 扫描正确（DMA 子项待实现）

## 理由

选内部 VREFINT 通道使真机 drivertest 无需任何外部布线即可跑，且其
±2 LSB 转换抖动天然满足 drivertest_adc 的 "两次读数须变化" 判据
（-d 1：需 delta≥2），而冻结的桩值 delta=0 永远无法通过 —— 保证测试
诚实反映真实硬件转换。外部/多通道/DMA 子项 EdgeSight 无需求，延后。
