# ADR-019: XSPI Flash 启动

## 状态

Done

## Phase

P2

## 目标

> GitHub Issue: #24
> 验证级别: MEASURED

实现从外部 XSPI Flash 启动 NuttX 固件，
替代 SRAM DEV boot 模式，支持固件持久化存储。

## 上下文

当前 P0 使用 SRAM DEV boot 模式（ADR-004），
固件需要每次通过 ST-Link 加载。
XSPI Flash 启动可以：
- 固件持久化，断电不丢失
- 支持 OTA 升级
- 释放 SRAM 空间给应用

DS14791 Section 6: Boot modes (XSPI boot)。

## 决策

EdgeSight XSPI Flash 启动方案：

1. **XSPI2 用于 AI 模型权重**: 内存映射到 0x70000000，XIP 模式
2. **XSPI1 用于代码存储**: NuttX 固件存放在 XSPI1 Flash
3. **FSBL (First Stage Boot Loader)**: 复用 ST 官方预编译 `ai_fsbl.hex`
   - FSBL 初始化 XSPI2 控制器
   - 配置 memory-mapped 模式
   - 跳转到主应用（NuttX）
4. **模型权重地址**: 0x70380000（与 stedgeai mpool 配置一致）
5. **Flash 型号**: MX25UW25645G（256MB，STM32N6570-DK 板载）

启动流程：
```
ROM Bootloader → FSBL (ai_fsbl.hex)
  → XSPI2 init (memory-mapped)
  → Jump to NuttX @ SRAM or XIP
```

初期仍使用 DEV boot + SRAM 加载开发，XSPI boot 在固件稳定后切换。

## 设计

### 模块架构

```
启动模式切换
├── DEV boot (当前, P0)
│   └── ST-Link → SRAM @ 0x34000400
│
└── XSPI boot (本 ADR)
    ├── ROM bootloader 从 XSPI Flash 加载
    ├── Flash 地址映射到内存空间
    └── 支持 XIP (Execute In Place)

链接脚本变更:
  .text : { *(.text*) } > FLASH (XSPI)
  .data : { *(.data*) } > SRAM AT> FLASH
  .bss  : { *(.bss*)  } > SRAM
```

### NuttX 框架对接

```
启动链变更:
  ROM bootloader
    → 从 XSPI Flash 加载固件到 SRAM (或 XIP)
    → 跳转到 _stext
    → __start() (与 ADR-002 相同)
    → nx_start()

OTA 升级:
  应用 → MTD write() → Flash 分区 A/B
    → 设置 boot flag → 复位 → 新固件启动
```
