# ADR-010: EXTI 扩展中断

## 状态

Done

## Phase

P1

## 目标

> GitHub Issue: #15
> 验证级别: QEMU

实现 EXTI（扩展中断）控制器驱动，支持 GPIO 引脚
边沿触发中断，为按键、外部事件提供中断机制。

## 上下文

STM32N6 的 EXTI 控制器将 GPIO 引脚的边沿变化
映射到 NVIC 中断线。每个 GPIO 端口可独立配置
上升沿/下降沿/双边沿触发。

DS14791 Section 11: EXTI。
NuttX 的 `gpint`（GPIO interrupt）框架依赖 EXTI。

## 决策

EdgeSight EXTI 使用方案：

1. **用户按键**: STM32N6570-DK 板载 USER 按键通过 EXTI 触发
   - 短按：显示统计信息
   - 长按：手动触发录像 / 重置跌倒状态
2. **SD 卡检测**: CD 引脚通过 EXTI 监测 SD 卡插拔（如果实现热插拔）
3. **PHY 中断**: LAN8742 INT# 引脚通过 EXTI 通知链路变化
4. **实现参考**: STM32H7 EXTI 驱动 (`stm32_exti_gpio.c`)，
   寄存器布局类似但 N6 新增了事件路由矩阵

NuttX 对接：通过 `stm32n6_gpiosetevent()` 注册回调。

## 设计

### 模块架构

```
EXTI 控制器
├── 16 条中断线 (EXTI0-EXTI15)
│   ├── 每条线可映射到任意 GPIO 端口
│   └── 例如: EXTI5 可映射到 PA5 或 PE5
│
├── 触发配置
│   ├── 上升沿触发 (RTSR)
│   ├── 下降沿触发 (FTSR)
│   └── 双边沿触发
│
└── 中断/事件模式
    ├── 中断模式 → NVIC
    └── 事件模式 → CPU 事件
```

### NuttX 框架对接

```
NuttX gpint 框架:
  gpint_pinconfig(pin, rising, falling, handler, arg)
    → 配置 EXTI 线
    → 注册中断处理函数

用户空间:
  /dev/gpintN → read() 阻塞等待中断
```
