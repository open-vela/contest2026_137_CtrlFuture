## 目标

> GitHub Issue: #36
> 验证级别: MEASURED

实现 STM32N6 LTDC（LCD-TFT Display Controller）驱动，
支持 RGB 接口 LCD 显示屏的帧缓冲传输。

## 上下文

STM32N647X0 有 LTDC 控制器，特性：
- 支持 RGB888/RGB565 像素格式
- 2 层叠加（Layer 1 + Layer 2）
- Alpha 混合（逐像素或全局）
- 最高 1024x768 分辨率（受限于像素时钟）
- 依赖 HPDMA（ADR-025）进行帧缓冲传输

DS14791 Section 35: LCD-TFT display controller (LTDC)。
LTDC 用于 HMI 显示、仪表盘、监控界面。

## 决策

采用 LTDC 双层架构 + 双缓冲前景方案：

1. **分辨率**: 800x480（匹配目标 LCD 面板）

2. **图层分配**:
   - Background Layer (Layer 0): 摄像头实时画面，RGB565 格式，单缓冲
   - Foreground Layer (Layer 1): UI 叠加层，ARGB4444 格式，双缓冲
   - 背景层直接从 DCMIPP 输出帧缓冲读取，前景层用于绘制检测框、文字等 OSD 信息

3. **双缓冲策略**: 前景层使用乒乓缓冲，在 VSYNC 中断时切换，避免撕裂

4. **DMA2D 加速**: 使用 DMA2D 进行矩形填充（清屏、绘制色块），减轻 CPU 负担

5. **像素格式选择**:
   - 背景 RGB565（16-bit）: 节省带宽，摄像头数据本身即 RGB565
   - 前景 ARGB4444（16-bit）: 支持透明度，用于 OSD 叠加，比 ARGB8888 节省一半带宽

实现文件：
- `app/edgesight/display_hal.h` — 显示 HAL 接口定义
- `app/edgesight/display_hal.c` — LTDC 初始化、图层配置、DMA2D 填充实现

## 设计

### 模块架构

```
LTDC 控制器
├── 时序生成
│   ├── 水平同步 (HSYNC)
│   ├── 垂直同步 (VSYNC)
│   ├── 数据使能 (DE)
│   └── 像素时钟 (PCLK)
│
├── 图层 (Layer 1/2)
│   ├── 帧缓冲基地址
│   ├── 像素格式 (RGB888/RGB565/ARGB8888)
│   ├── 窗口位置和大小
│   ├── Alpha 混合 (全局/逐像素)
│   └── 色键 (Color Keying)
│
└── 输出
    ├── RGB 并行接口 (24-bit)
    └── 像素时钟 (最高 ~50MHz)
```

### NuttX 框架对接

```
NuttX framebuffer 框架:
  fb_register("/dev/fb0", &ltdc_fb)

应用层:
  fd = open("/dev/fb0", O_RDWR)
  ioctl(fd, FBIOGET_VIDEOINFO, &vinfo)
  → vinfo.xres, vinfo.yres, vinfo.bpp
  buf = mmap(NULL, size, PROT_WRITE, MAP_SHARED, fd, 0)
  → 直接写入帧缓冲
  ioctl(fd, FBIOPAN_DISPLAY, &vinfo)
  → 切换显示

图形栈:
  LittlevGL / LVGL → /dev/fb0 → LTDC → LCD
```

### 数据流

```
显示更新:
  应用 → mmap 写入帧缓冲
    → LTDC 从 SRAM 读取 (HPDMA)
    → 像素格式转换
    → 时序生成 → RGB 输出 → LCD 面板

双缓冲:
  buf0 → LTDC 显示中
  buf1 → 应用绘制中
  FBIOPAN_DISPLAY → 交换 → 无撕裂

## 理由

1. **双层分离**: 将摄像头画面和 UI 叠加分层，避免每帧重绘整个画面，只需更新前景层即可。
2. **ARGB4444 前景**: 在保持透明度支持的同时，比 ARGB8888 节省 50% 带宽和显存，对于简单 OSD（检测框、文字）已足够。
3. **DMA2D 矩形填充**: 清除/绘制矩形区域由硬件完成，CPU 可同时处理推理结果的后处理。
4. **背景单缓冲**: 摄像头输出帧率与显示刷新同步，无需额外缓冲；前景需要双缓冲是因为 CPU 绘制时间不确定。
