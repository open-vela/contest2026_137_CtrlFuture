# ADR-004: 真机串口验证（DEV boot SRAM 加载）

## 状态

<!-- 合法值: Proposed | Accepted | Deprecated -->

Proposed

## Phase

P0

## 目标

> GitHub Issue: #9
> 验证级别: MEASURED

在 STM32N6570-DK 开发板上，通过 DEV boot 模式从 SRAM 加载 NuttX
固件，USART1 (PE5/PE6) 输出 NSH shell 提示符，验证完整启动链
在真实硬件上工作。

## 上下文

ADR-001/002/003 已完成 CI 编译验证（BUILD 级别）。
P0 的最终目标是真机串口输出 `nsh>`，这需要：

1. **DEV boot 模式**：STM32N6 无内部 flash，代码必须通过
   ST-Link 加载到 SRAM（0x34000400）。ROM bootloader 在
   SRAM 最前 1KB 放置 boot header。
2. **ST-Link VCP**：STM32N6570-DK 板载 ST-Link 提供虚拟串口，
   连接到 USART1 PE5(TX)/PE6(RX)。
3. **工具链**：需要 STM32CubeProgrammer 或 OpenOCD 进行
   SRAM 加载和调试。

## 决策

使用 STM32CubeProgrammer CLI 通过 ST-Link 将 nuttx.bin 加载到 SRAM 0x34000400。
开发板设置 DEV boot 模式（BOOT0=1），确保 CPU 从 SRAM 启动。
串口终端配置：115200 波特率，8N1，无流控。
验证成功标准：串口终端显示 `nsh>` 提示符。

加载命令示例：
```
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG \
  -w nuttx.bin 0x34000400 \
  -s 0x34000400
```

硬件连接：ST-Link VCP 自动映射到 USART1 PE5(TX)/PE6(RX)，
主机端通过 /dev/ttyACM0（Linux）或 COMx（Windows）连接。

## 设计

### 模块架构

本 ADR 是验证里程碑，不新增代码文件。
验证的是 ADR-002 + ADR-003 的芯片驱动在真实硬件上的行为。

### NuttX 框架对接

验证的完整启动链：

```
ST-Link 加载 nuttx.bin → SRAM @ 0x34000400
  → CPU 从 _stext 开始执行
    → __start() [stm32n6_start.c]
      → BSS 清零 + DATA 拷贝
      → stm32n6_clockconfig()  ← HSI 64MHz
      → stm32n6_lowsetup()     ← USART1 PE5/PE6 AF7
      → nx_start()
        → up_irqinitialize()   ← NVIC 初始化
        → up_allocate_heap()   ← 堆注册
        → arm_serialinit()     ← 注册 /dev/console
        → up_timer_initialize()← SysTick @ 100Hz
        → nsh_main()           ← NSH shell 启动
          → 输出 "nsh>" 提示符
```

### 数据流

```
NSH 输入:
  用户键盘 → ST-Link VCP → USART1 RX (PE6)
    → USART1 RXNE 中断 → stm32n6_interrupt()
      → uart_recvchars() → NSH readline

NSH 输出:
  NSH printf → uart_send() → USART1 TX (PE5)
    → USART1 TXE 中断 → stm32n6_interrupt()
      → uart_xmitchars() → ST-Link VCP → 串口终端
```

## 理由

选择 STM32CubeProgrammer 而非 OpenOCD，因为其对 STM32N6 的支持更成熟，
且 ST-Link 固件更新和 SRAM 加载流程均由 ST 官方工具链保证兼容性。
DEV boot 模式是 STM32N6 无内部 Flash 芯片的标准开发调试方式。
115200 波特率在 HSI 64MHz 下误差极小，兼容性最佳。
