# ADR-023: USB OTG HS

## 状态

PARTIAL（`stm32n6_otg.c` 仅寄存器骨架，host 模式 `return -ENOSYS`、
多处 TODO，未接入 defconfig。USB 需物理主机枚举，远程真机无法自环
验证；EdgeSight 不走 USB，延后 P5）

## Phase

P3

## 目标

> GitHub Issue: #28
> 验证级别: MEASURED

实现 STM32N6 USB OTG HS 驱动，支持 USB 设备/主机模式，
用于 USB CDC（虚拟串口）、MSC（大容量存储）等。

## 上下文

STM32N647X0 有 USB OTG HS 控制器，支持：
- USB 2.0 High-Speed (480Mbps)
- OTG（On-The-Go）设备/主机切换
- 多种设备类（CDC/MSC/HID/Audio）

DS14791 Section 38: USB OTG HS。
电源管理依赖 ADR-009（PWR）。

## 决策

EdgeSight 当前不使用 USB OTG，优先级低。

- 控制台使用 USART1（ST-Link VCP），不需要 USB CDC。
- 数据导出走 Ethernet（MQTT 上传），不需要 USB MSC。
- 调试使用 ST-Link SWD，不需要 USB DFU。

可选的 P5 功能：USB Mass Storage 模式将 SD 卡导出为 U 盘，
方便现场人员直接拷贝录像文件。该功能延后至核心功能完成后再评估。

## 实现现状（2026-07-30 修正）

`arch/arm/stm32n6/src/stm32n6_otg.c`（原 ADR「文件」段写 stm32n6_otghs.c，
实际文件名为 stm32n6_otg.c）为寄存器骨架：定义了 OTG_HS 基址与
GOTGCTL/GOTGINT 等寄存器偏移，但 host 模式 `return -ENOSYS`
（"otg: host mode not implemented"），含多处 TODO，未接入任何 defconfig。

**远程真机无法验证**：USB 需物理主机端枚举（PHY 引脚硬连线，无软件
自环模式），远程调试板无物理主机连接。EdgeSight 数据路径（摄像头→
NPU→Ethernet）不涉及 USB。故判定 PARTIAL 并延后至 P5 产品化阶段。

## 设计

### 模块架构

```
USB OTG HS 控制器
├── 设备模式
│   ├── CDC ACM (虚拟串口)
│   ├── MSC (大容量存储)
│   ├── HID (人机接口)
│   └── 复合设备
│
├── 主机模式
│   ├── USB Flash 驱动器
│   ├── USB 键盘/鼠标
│   └── USB Hub
│
└── OTG 模式
    └── 自动设备/主机切换
```

### NuttX 框架对接

```
NuttX USB 设备栈:
  usbdev_register(&usbdev_driver)
    → /dev/ttyACM0 (CDC)

NuttX USB 主机栈:
  usbhost_register(&usbhost_driver)
    → 枚举连接的 USB 设备
```

## 理由

EdgeSight 核心数据路径（摄像头→NPU→网络）不涉及 USB。
开发资源应优先投入关键外设（Ethernet、DCMIPP、XSPI）。
USB MSC 作为便利性功能可在产品化阶段（P5）再添加。
