# ADR-036: Neural-ART NPU

## Renode 模型说明

`tests/renode/peripherals/STM32N6_NPU.cs` 是当前测试基础设施中的
NPU 仿真模型。需要明确：CMSIS `stm32n647xx.h` 只定义了
`NPU_PRESENT`/`NPU_BASE`（表示存在该 IP 及其基地址），**完全没有
`NPU_TypeDef` 结构体或任何寄存器偏移/位域定义**——Neural-ART NPU
的寄存器手册未随 CMSIS 头文件公开。因此该模型的 `CR@0x00/SR@0x04/
IER@0x08/VER@0x0C/CFG@0x10` 布局是团队自定义的占位设计，仅用于
验证总线可达性和中断连线，不代表真实硬件寄存器语义。未来实现真实
`stm32n6_npu.c` 驱动时，必须以 ST `stedgeai` 运行时库随附文档或
DS14791 NPU 章节的专门寄存器手册为准，而不能参照本模型的偏移布局。

## 上下文

STM32N647X0 内置 Neural-ART NPU 加速器，特性：
- 600 Gops 算力（INT8）
- 支持 CNN、Transformer、LSTM 等模型
- 硬件卷积、池化、全连接、激活函数
- 2MB 专用 SRAM（NPU SRAM）
- 依赖 HPDMA（ADR-025）进行数据搬运

DS14791 Section 43: NPU (Neural Processing Unit)。
NPU 是 STM32N6 最大卖点，用于边缘 AI 推理。

## 决策

采用 ST stedgeai 运行时库，双模型架构（检测 + 姿态），模型权重存储于外部 Flash：

1. **运行时库**: 使用 ST 提供的 `NetworkRuntime1200_CM55_GCC.a` 静态库
   - stedgeai 运行时封装了 NPU 硬件调度、内存管理、层间数据搬运
   - 应用层通过 stedgeai API 加载和执行模型

2. **双模型架构**:
   - 模型 1: YOLO-X Nano — 人体检测（输出 bounding box + confidence）
   - 模型 2: MoveNet Lightning — 人体姿态估计（输出 17 个关键点坐标）
   - 推理流程: 先 YOLO-X 检测人体区域，再对检测区域运行 MoveNet 估计姿态

3. **模型格式与存储**:
   - 模型通过 STM32Cube.AI 工具预编译为 NPU 二进制格式（非 ONNX/TFLite 运行时解析）
   - 模型权重存储在 XSPI2 外部 Flash，映射地址 `0x70380000`
   - 运行时通过 memory-mapped 方式直接读取权重，无需加载到 SRAM

4. **内存分配**:
   - NPU 激活缓冲区（中间层计算结果）分配在 AXISRAM3-6
   - 输入/输出张量在通用 SRAM 中，由应用管理
   - 权重只读，直接从 Flash XIP 访问

5. **推理触发**: 由 camera_hal 帧回调驱动，每帧触发一次 YOLO-X 推理，
   检测到人体时追加 MoveNet 推理

实现文件：
- `app/edgesight/npu_hal.h` — NPU HAL 接口定义（初始化、推理、结果获取）
- `app/edgesight/npu_hal.c` — stedgeai 运行时封装、双模型调度、内存配置

## 设计

### 模块架构

```
Neural-ART NPU
├── 计算引擎
│   ├── 卷积加速器 (Conv2D)
│   ├── 矩阵乘法 (MatMul)
│   ├── 池化 (Max/Average Pool)
│   ├── 激活函数 (ReLU/Sigmoid/Tanh)
│   └── 量化支持 (INT8/INT16)
│
├── 内存
│   ├── NPU SRAM (2MB, 专用)
│   ├── 权重加载 (Flash → NPU SRAM)
│   └── 激活缓存 (SRAM ↔ NPU SRAM)
│
└── 模型格式
    ├── STM32Cube.AI 导出 (.onnx → .tflite)
    ├── 量化模型 (INT8)
    └── 运行时模型加载
```

### NuttX 框架对接

```
NPU 设备接口:
  register_driver("/dev/npu0", &npu_ops)

应用层:
  fd = open("/dev/npu0", O_RDWR)
  ioctl(fd, NPU_IOC_LOAD_MODEL, &model_info)
  ioctl(fd, NPU_IOC_SET_INPUT, &input_buf)
  ioctl(fd, NPU_IOC_INVOKE, 0)
  ioctl(fd, NPU_IOC_GET_OUTPUT, &output_buf)
  → 推理结果

典型 AI 流程:
  摄像头 → DCMIPP → 预处理
    → NPU 推理 → 后处理
    → 结果显示 (LTDC) / 网络上传 (GMAC)
```

### 数据流

```
推理流程:
  1. 加载模型: Flash → NPU SRAM
  2. 输入数据: SRAM → NPU SRAM (HPDMA)
  3. NPU 计算: 各层依次执行
  4. 输出结果: NPU SRAM → SRAM (HPDMA)
  5. 后处理: CPU 解析推理结果

实时目标检测:
  DCMIPP → 帧缓冲 (320x240)
    → NPU → 检测结果 (bbox + class)
    → CPU 绘制框 → LTDC → LCD

## 理由

1. **stedgeai 运行时**: ST 官方提供的 NPU 运行时库已优化 NPU 调度和内存管理，比手动操作 NPU 寄存器可靠性高且开发周期短。
2. **预编译模型格式**: NPU 需要特定二进制格式（非通用 ONNX），预编译避免了运行时模型解析的内存和时间开销。
3. **双模型级联**: 先检测再估计姿态比单一大模型更灵活——YOLO-X 快速筛选感兴趣区域，MoveNet 只处理有人体的 crop，整体效率高于全图姿态估计。
4. **XSPI2 Flash 存储权重**: 模型权重通常数 MB，放入片内 SRAM 不现实；XSPI2 支持 memory-mapped XIP，读取延迟可接受且不占用宝贵的 SRAM 空间。
5. **AXISRAM3-6 用于激活**: 这些 SRAM bank 靠近 NPU，带宽充足，且不与 CPU 通用数据竞争。
