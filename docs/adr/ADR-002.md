# ADR-002: 最小启动（RCC/GPIO/USART1/IRQ/heap/start）

## 状态

Accepted

## Phase

P0

## 目标

> GitHub Issue: #7
> 验证级别: BUILD

STM32N6 芯片驱动通过编译，包含最小启动所需的全部模块：
时钟、GPIO、USART1 串口、中断控制器、堆分配、启动代码。

## 上下文

STM32N647X0 是 Cortex-M55（ARMv8.1-M）芯片，NuttX 上游尚无
STM32N6 系列支持。需要从零实现最小芯片驱动集，使固件能从
SRAM DEV boot 模式启动并输出串口日志。

参考 STM32H7 和 MPS3-AN547 的已有实现，结合 DS14791 datasheet。

## 决策

最小驱动集包含 8 个源文件：

| 文件 | 功能 |
|------|------|
| `stm32n6_start.c` | 复位入口，BSS/DATA 初始化，调用 `nx_start()` |
| `stm32n6_rcc.c` | HSI 64MHz 时钟，GPIOE + USART1 时钟使能 |
| `stm32n6_gpio.c` | PE5/PE6 配置为 USART1 AF7 |
| `stm32n6_lowputc.c` | USART1 低级初始化和轮询发送 |
| `stm32n6_serial.c` | NuttX serial 框架驱动，中断收发 |
| `stm32n6_irq.c` | NVIC 初始化、IRQ enable/disable/prioritize |
| `stm32n6_allocateheap.c` | SRAM 堆区域注册 |
| `stm32n6_gpio.h` | GPIO 引脚定义和 AF 映射 |

PLL 配置暂不实现，CPU 运行在 HSI 64MHz。

## 设计

### 模块架构

8 个文件按启动顺序形成调用链，分为 4 个层次：

```
┌─────────────────────────────────────────────────────┐
│ NuttX 内核                                           │
│   nx_start() ← stm32n6_start.c 调用                 │
│     → up_initialize()                                │
│       → arm_serialinit() ← stm32n6_serial.c 注册     │
│     → clock_initialize()                             │
│       → up_timer_initialize() ← ADR-003              │
└─────────────────────────────────────────────────────┘
         ↑ 启动后由 NuttX 调度器管理

┌─────────────────────────────────────────────────────┐
│ 芯片驱动层 (本 ADR)                                  │
│                                                      │
│  __start() ← 复位向量入口                            │
│    ├── BSS 清零 + DATA 拷贝                          │
│    ├── stm32n6_clockconfig() ← RCC: HSI + 时钟门控  │
│    ├── stm32n6_lowsetup()   ← GPIO + USART1 初始化  │
│    ├── stm32_boardinitialize() ← 板级回调(空实现)    │
│    ├── arm_earlyserialinit() ← serial 框架初始化     │
│    └── nx_start() ← 进入 NuttX 内核                  │
│                                                      │
│  stm32n6_irq.c ← NVIC 管理，被 NuttX irq.h 调用    │
│  stm32n6_allocateheap.c ← 堆注册，被 NuttX 调用     │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ 硬件抽象层                                           │
│  stm32_memorymap.h — 外设基地址定义                  │
│  chip.h — 中断数、优先级位数                         │
│  irq.h — IRQ 编号定义 (196 个外部中断)               │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ 链接脚本                                             │
│  flash.ld — SRAM @ 0x34000400, 4.2MB                │
│  _stext → .text → .data → .bss → heap              │
└─────────────────────────────────────────────────────┘
```

### NuttX 框架对接

**启动链**：`__start()` 是复位向量入口（链接脚本 `ENTRY(_stext)`）。
它不是 NuttX API，而是芯片启动代码，在 NuttX 内核接管前执行。

**串口驱动**：`stm32n6_serial.c` 实现 NuttX `uart_ops_s` 接口：
- `g_uart_ops` 结构体注册 12 个回调函数
- `arm_serialinit()` 调用 `uart_register("/dev/console", &g_usart1port)`
  注册为控制台设备
- 中断处理：`irq_attach(STM32_IRQ_USART1, stm32n6_interrupt, dev)`

**IRQ 驱动**：`stm32n6_irq.c` 实现 NuttX `up_*irq*` API：
- `up_irqinitialize()` — NVIC 初始化，设置向量表、默认优先级
- `up_enable_irq()` / `up_disable_irq()` — IRQ 使能/禁用
- `up_prioritize_irq()` — 中断优先级设置

**堆注册**：`stm32n6_allocateheap.c` 实现 `up_allocate_heap()`：
- 告诉 NuttX 堆的起始地址（`g_idle_topstack`）和大小
- NuttX 的 `kmm_malloc()` 系列函数使用此堆

### 数据流

```
复位 → __start()
  │
  ├─ BSS 清零 (_sbss → _ebss)
  ├─ DATA 拷贝 (_eronly → _sdata → _edata)
  │
  ├─ stm32n6_clockconfig()
  │    ├─ rcc_enablehsi()        ← RCC_CR.HSION + HSIRDY 轮询
  │    ├─ RCC_AHB4ENR |= GPIOE  ← PE 时钟门控
  │    └─ RCC_APB2ENR |= USART1 ← USART1 时钟门控
  │
  ├─ stm32n6_lowsetup()
  │    ├─ stm32n6_configgpio(USART1_TX) ← PE5 AF7
  │    ├─ stm32n6_configgpio(USART1_RX) ← PE6 AF7
  │    └─ USART1_BRR = 64MHz / 115200   ← 波特率
  │
  └─ nx_start() → NuttX 内核接管
       ├─ up_irqinitialize()     ← NVIC 初始化
       ├─ up_allocate_heap()     ← 堆注册
       ├─ arm_serialinit()       ← 注册 /dev/console
       └─ nsh_main()             ← NSH shell
```

## 实现说明

### 关键寄存器配置

**RCC_CR (0x46028000 + 0x00)**：
- bit 0 `HSION` — 写 1 启动内部高速振荡器
- bit 2 `HSIRDY` — 只读，HSI 稳定后自动置 1
- 代码在 `rcc_enablehsi()` 中先写 HSION，再轮询 HSIRDY。
  这是 STM32 标准的时钟启动模式，所有 STM32 系列通用。

**USART_BRR (波特率寄存器)**：
- `BRR = fck / baud`，fck = HSI 64MHz
- 115200 波特率 → BRR = 64000000 / 115200 ≈ 556 (0x22C)
- 代码使用四舍五入：`(HSI + baud/2) / baud`

**GPIO AFRL/AFRH (复用功能寄存器)**：
- 每个引脚占 4 位，AF7 = USART1
- PE5 在 AFRL[23:20]，PE6 在 AFRL[27:24]
- `stm32n6_configgpio()` 先设 MODER=0b10 (AF模式)，
  再设 AFRL/AFRH 对应 4 位为 7

**NVIC 向量表**：
- `NVIC_VECTAB` 寄存器指向 `_vectors` 数组（链接脚本定义）
- ARMv8-M 向量表布局：前 16 个是系统异常，之后是外部中断
- `irq.h` 定义了 196 个外部中断（`STM32_IRQ_NEXTINTS = 196`）

### 代码模式

**寄存器访问**：统一使用 NuttX 的 `getreg32()` / `putreg32()` 宏，
而非直接指针解引用。这些宏在 `arm_internal.h` 中定义，
提供内存屏障和调试追踪能力。

**GPIO 编码**：`stm32n6_configgpio()` 接受一个 32 位编码值，
通过位域提取 port/pin/mode/af/speed/pupd/otype。
这是 STM32 系列的通用模式（参照 `stm32h7/stm32_gpio.c`），
好处是引脚配置可以在头文件中用宏定义，
如 `GPIO_USART1_TX` 展开为一个 32 位常量。

**Serial 驱动**：NuttX serial 框架要求实现 `uart_ops_s` 结构体的
12 个回调。关键设计：
- TX/RX 各有 64 字节环形缓冲区
- 中断驱动：`stm32n6_interrupt()` 检查 ISR 的 RXNE/TXE 位
- `uart_recvchars()` / `uart_xmitchars()` 是 NuttX 提供的
  通用函数，负责从/向环形缓冲区搬移数据

### 踩坑与解决

1. **`stm32_boardinitialize` 命名问题**：NuttX 启动链调用的是
   `stm32_boardinitialize()`（全小写 `board`），但代码一度写成了
   `stm32_boardInitialize()`（驼峰）。这导致链接时报 undefined symbol。
   修复：统一为 NuttX 约定的 `stm32_boardinitialize`。

2. **DEV boot 偏移 0x400**：STM32N6 DEV boot 模式下，
   ROM bootloader 在 SRAM 最前面 1KB 放置 boot header。
   链接脚本必须用 `ORIGIN = 0x34000400` 而非 `0x34000000`。
   忘记这个偏移会导致向量表地址错误，系统 HardFault。

3. **`arm_lowputc` 轮询死等**：`arm_lowputc()` 中的 TXE 轮询
   没有超时保护。在 USART1 时钟未使能时会永久死等。
   当前实现依赖 `stm32n6_clockconfig()` 先执行，
   后续 ADR-012 扩展串口时需要为每个 UART 独立使能时钟。

## 理由

选择 HSI 64MHz 而非立即配置 PLL 的原因：
- DEV boot 模式下 ROM bootloader 已将 HSI 配置好
- 减少初始化复杂度，PLL 可在后续 ADR-005 中实现
- 64MHz 足以驱动 USART1 串口调试

选择 PE5/PE6 作为 USART1 引脚：
- STM32N6570-DK 开发板 ST-Link VCP 连接到 PE5(TX)/PE6(RX)
- AF7 功能，参照 DS14791 Table 30
