# ADR-017: MPU 内存保护

## 状态

Accepted

## Phase

P1

## 目标

> GitHub Issue: #22
> 验证级别: QEMU

配置 Cortex-M55 的 MPU（内存保护单元），
实现内存区域访问权限控制，增强系统健壮性。

## 上下文

Cortex-M55 支持 ARMv8-M MPU，最多 16 个区域。
MPU 可以防止：
- 用户代码访问内核内存
- 野指针破坏关键数据
- 栈溢出覆盖其他区域

DS14791 Section 3.4: MPU。
NuttX 支持 MPU 保护的用户模式。

## 决策

EdgeSight MPU 区域分配：

| Region | 地址范围 | 用途 | 属性 |
|--------|----------|------|------|
| 0 | 0x70000000-0x7FFFFFFF | XSPI Flash (代码+模型) | RO, Cacheable, XN for data |
| 1 | 0x34000000-0x3407FFFF | FLEXMEM (NuttX heap) | RW, Cacheable |
| 2 | 0x34080000-0x3419BFFF | AXISRAM1 (framebuf) | RW, Cacheable |
| 3 | 0x3419C000-0x341FFFFF | AXISRAM2 (camera DMA) | RW, Non-cacheable |
| 4 | 0x34200000-0x343BFFFF | AXISRAM3-6 (NPU) | RW, Non-cacheable, XN |
| 5 | 0x40000000-0x5FFFFFFF | 外设空间 | RW, Device, XN |
| 6 | 0x00000000-0x0000FFFF | ITCM | RO, Executable |
| 7 | 0x20000000-0x2001FFFF | DTCM | RW, XN |

关键策略：
- NPU SRAM (AXISRAM3-6) 设为 Non-cacheable，避免 CPU cache 与 NPU 直接访问的一致性问题
- Camera DMA 目标 (AXISRAM2) 设为 Non-cacheable，避免 DMA 一致性开销
- 外设空间设为 Device 属性，保证访问顺序和不合并

## 设计

### 模块架构

```
MPU 区域规划 (16 个区域)
├── Region 0: Flash (只读, 可执行)
├── Region 1: SRAM (读写, 不可执行)
├── Region 2: 外设 (读写, 不可执行, Device)
├── Region 3: ITCM (只读, 可执行)
├── Region 4: DTCM (读写, 不可执行)
├── Region 5: 栈保护区域 (无访问, 触发异常)
└── Region 6-15: 用户自定义

MPU 属性:
├── XN (eXecute Never) — 禁止执行
├── AP (Access Permission) — 读/写/特权
├── TEX/SCB — Cache 策略
└── SH (Shareable) — 多核共享
```

### NuttX 框架对接

```
NuttX MPU API:
  mpu_control()           ← 使能/禁用 MPU
  mpu_configure_region()  ← 配置区域
  mpu_showinfo()          ← 调试输出

用户模式:
  up_task_startup() → 配置用户 MPU 区域
  SVC 指令 → 切换到特权模式
```
