# ADR-015: 看门狗（IWDG/WWDG）

## 状态

Accepted

## Phase

P1

## 目标

> GitHub Issue: #20
> 验证级别: MEASURED

实现 STM32N6 看门狗驱动，支持独立看门狗（IWDG）
和窗口看门狗（WWDG），防止软件死锁导致系统挂起。

## 上下文

STM32N6 有 2 种看门狗：
- IWDG：独立看门狗，使用 LSI 时钟，不受主时钟影响
- WWDG：窗口看门狗，使用 APB 时钟，有精确喂狗窗口

DS14791 Section 34: IWDG/WWDG。
看门狗是嵌入式系统可靠性保障的关键组件。

## 决策

使用 IWDG（独立看门狗），配置如下：

- **超时时间**: 4 秒（预分频 64，重载值 2000）
- **喂狗位置**: 主循环（NSH idle loop 或专用 work_queue 任务）
- **复位策略**: 超时未喂狗则硬件自动复位 CPU
- **使能时机**: 系统稳定启动后（board_late_initialize 完成后）再使能，
  避免启动阶段初始化耗时导致误复位

不使用 WWDG（窗口看门狗），EdgeSight 不需要精确喂狗窗口约束。
IWDG 使用 LSI 时钟，独立于主时钟，即使主时钟故障也能触发复位。

## 设计

### 模块架构

```
IWDG (独立看门狗)
├── 时钟源: LSI ~32kHz
├── 预分频器: 4/8/16/32/64/128/256
├── 重载值: 12-bit (0-4095)
├── 超时范围: ~0.1ms ~ 32s
└── 特性: 独立于主时钟, 一旦使能无法禁用

WWDG (窗口看门狗)
├── 时钟源: APB (经过分频)
├── 窗口值: 7-bit
├── 计数器: 7-bit
└── 特性: 有精确喂狗窗口, 可产生早期中断
```

### NuttX 框架对接

```
NuttX watchdog 框架:
  watchdog_register("/dev/watchdog0", &iwdg_dev)
    → open("/dev/watchdog0")
    → ioctl(WDIOC_SETTIMEOUT, &timeout)
    → ioctl(WDIOC_START)
    → 定期 ioctl(WDIOC_KEEPALIVE) ← 喂狗

自动喂狗 (board_bringup.c):
  board_wdog_init() → 启动看门狗
  work_queue() → 定期喂狗
```

## 理由

IWDG 简单可靠，独立于主时钟，适合 EdgeSight 长期无人值守运行场景。
4 秒超时兼顾了 NPU 推理延迟（单帧 < 1s）和异常检测灵敏度。
延迟使能避免了启动阶段（摄像头初始化、网络 DHCP）的误触发。
