# ADR-007: Cache 配置（ICACHE + DCACHE）

## 状态

Accepted

## Phase

P1

## 目标

> GitHub Issue: #12
> 验证级别: MEASURED

配置 Cortex-M55 的指令缓存（ICACHE）和数据缓存（DCACHE），
提升代码执行和数据访问性能，为 DMA 一致性奠定基础。

## 上下文

Cortex-M55 集成 L1 指令缓存和数据缓存。
在 SRAM DEV boot 模式下，代码从 SRAM 执行，
缓存可以显著减少总线访问延迟。

DS14791 Section 3.3: Cortex-M55 缓存架构。
缓存与 DMA 的一致性问题在 ADR-011（GPDMA）中处理。

## 决策

在启动早期（`stm32n6_start.c` 调用 `nx_start()` 之前）使能 ICACHE 和 DCACHE。

策略：
1. **ICACHE**: 直接使能，write-through，无需额外管理
2. **DCACHE**: 使能 write-back 模式，DMA 操作前后需 clean/invalidate
3. **NPU 一致性**: NPU 访问的 AXISRAM3-6 配置为 non-cacheable（通过 MPU）
4. **Camera DMA 一致性**: DCMIPP DMA 目标缓冲区在使用前 invalidate

参考 ST 官方例程，在 FSBL main.c 中：
```c
SCB_EnableICache();
SCB_EnableDCache();
```

NuttX 中通过 CMSIS SCB API 或 NuttX up_enable_icache/dcache 实现。

## 设计

### 模块架构

```
Cortex-M55 缓存子系统
├── ICACHE (指令缓存)
│   ├── 通常只读，自动管理
│   └── 自修改代码时需 invalidate
│
└── DCACHE (数据缓存)
    ├── 读/write-back 策略
    ├── DMA 传输时需 clean/invalidate
    └── MPU 区域可配置 cache 策略
```

### NuttX 框架对接

```
NuttX 缓存 API:
  up_enable_icache()         ← 使能指令缓存
  up_enable_dcache()         ← 使能数据缓存
  up_disable_dcache()        ← 禁用数据缓存
  up_clean_dcache(addr, len) ← 回写脏行
  up_invalidate_dcache(addr, len) ← 无效化
  up_flush_dcache(addr, len) ← 回写 + 无效化

启动时:
  stm32n6_clockconfig()
    → up_enable_icache()     ← 启动早期使能
    → up_enable_dcache()
```

### 数据流

```
CPU 读取:
  CPU → DCACHE → [命中] → 返回数据
                → [未命中] → AXI SRAM → 填充 cache line → 返回

DMA 传输前 (发送):
  CPU → DCACHE clean → 确保数据写入 SRAM
  DMA → SRAM → 外设

DMA 传输后 (接收):
  DMA → 外设 → SRAM
  CPU → DCACHE invalidate → 强制从 SRAM 重新读取
```

## 理由

800MHz CPU 访问 AXISRAM 有多周期延迟，ICACHE/DCACHE 可将常用代码和数据
保持在 L1 中，显著降低访问延迟。NPU SRAM 区域设为 non-cacheable 避免
一致性问题，因为 NPU 通过独立总线直接访问。
