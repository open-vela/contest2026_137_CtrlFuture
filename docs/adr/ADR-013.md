# ADR-013: SPI 驱动（SPI1-6）

## 状态

PARTIAL（`stm32n6_spi.c` 是完整的寄存器编程驱动，非 stub；但未接入
defconfig、无板级引脚接线、无真机总线验证。下方「决策」原文
「暂不实现」已 stale——驱动实际已存在，见「实现现状」）

## Phase

P1

## 目标

> GitHub Issue: #18
> 验证级别: MEASURED

实现 STM32N6 SPI 驱动，支持 SPI1-6 全部实例，
支持主/从模式、DMA 传输、多种时钟极性/相位。

## 上下文

STM32N647X0 有 6 个 SPI 实例（SPI1-6），
支持最高 80MHz 时钟频率。DS14791 Section 30: SPI。

SPI 用于连接外部 Flash、传感器、显示屏等。
DMA 模式可实现零拷贝高速传输（依赖 ADR-011）。

## 决策

EdgeSight 项目不直接使用 SPI 外设，优先级低：

- 摄像头接口使用 CSI-2（DCMIPP，非 SPI）
- 存储使用 SDMMC1（SD 卡）和 XSPI（外部 Flash）
- 网络使用 Ethernet RMII（非 SPI）

SPI 驱动暂不实现。如后续需要连接 SPI 外设（如外部传感器），
再按 NuttX stm32h7 参考实现移植。当前 Phase 内无阻塞路径依赖 SPI。

## 实现现状（2026-07-30 修正）

上方「决策」原文（暂不实现）已 stale：`arch/arm/stm32n6/src/stm32n6_spi.c`
实际已是一个完整的寄存器编程驱动（SPI1-6 base + CFG1/CPOL/CPHA 配置 +
`spi_exchange`，通过 `spi_putreg/getreg` 访问器操作硬件，非空 stub），
且已列入 `Make.defs` 编译。

未达 MEASURED 的原因不是缺代码，而是缺**接线 + 真机验证**：

- 未在任何 defconfig 使能（无 `CONFIG_STM32_SPI*`）。
- 无板级引脚 AF 定义（ADR-006 只在设计段列了通用 `GPIO_SPI1_SCK`）。
- STM32 SPI **无片内自环位**，真机功能验证需外部把 MOSI 接到 MISO
  的 1 根跳线做回环。远程真机无人接线，此步暂不可行。

因此判定 PARTIAL：驱动完整、可编译，但未接线、未做真机总线数据往返。

## 设计

### 模块架构

```
NuttX SPI 框架
├── spi_dev_s — SPI 设备接口
│   ├── spi_select()     ← 片选
│   ├── spi_setfrequency() ← 时钟频率
│   ├── spi_setmode()    ← CPOL/CPHA
│   ├── spi_exchange()   ← 数据交换
│   └── spi_send()/recv() ← 单向传输
│
└── STM32N6 SPI 驱动
    ├── 中断模式 (默认)
    └── DMA 模式 (高性能, 依赖 ADR-011)
```

### NuttX 框架对接

```
SPI 设备注册:
  spi_register(spi_dev, bus_num)
    → /dev/spiN

外设驱动使用:
  struct spi_dev_s *spi = stm32n6_spibus_initialize(1)
  SPI_SELECT(spi, SPIDEV_FLASH, true)
  SPI_EXCHANGE(spi, tx_buf, rx_buf, len)
  SPI_SELECT(spi, SPIDEV_FLASH, false)
```

### 数据流

```
SPI DMA 发送:
  应用 → SPI TX buffer → DCACHE clean → GPDMA
    → SPI TXDR → MOSI 引脚

SPI DMA 接收:
  MISO 引脚 → SPI RXDR → GPDMA
    → SPI RX buffer → DCACHE invalidate → 应用
```

## 理由

EdgeSight 所有高速外设（摄像头、存储、网络）均不走 SPI 总线。
将有限开发资源集中在关键路径（CSI-2、SDMMC、Ethernet）上，
SPI 驱动可在后续迭代中按需添加。
