# ADR-018: XSPI 接口驱动

## 状态

Accepted

## Phase

P2

## 目标

> GitHub Issue: #23
> 验证级别: MEASURED

实现 STM32N6 XSPI（扩展 SPI）接口驱动，
支持连接外部 NOR/NAND Flash、PSRAM 等存储器。

## 上下文

STM32N6 有 2 个 XSPI 实例（XSPI1/2），
支持 1/2/4/8 线 SPI 协议，最高时钟频率 200MHz。
DS14791 Section 32: XSPI。

XSPI 用于连接外部 Flash（ADR-019 启动介质），
也可连接 PSRAM 扩展内存。

## 决策

EdgeSight 使用双 XSPI 接口，配置如下：

- **XSPI2**: 内存映射模式（Memory-mapped），地址 0x70000000，
  用于存放 AI 模型权重（只读访问），NPU 直接从该地址读取推理数据。
  使用 Macronix MX25UW25645G（256Mbit Octo-SPI NOR Flash）。
- **XSPI1**: 可选 XIP（Execute-In-Place）模式，用于代码执行扩展（P3 以后考虑）。
- **传输模式**: DTR（Double Transfer Rate）Octo-SPI，最大化带宽。
- **时钟频率**: 目标 100MHz DDR（等效 200MHz 吞吐）。

优先实现 XSPI2 内存映射模式（模型权重加载为关键路径），
XSPI1 XIP 模式在 SRAM 不够用时再实现。

## 设计

### 模块架构

```
XSPI 接口
├── 协议模式
│   ├── 1 线 SPI (经典)
│   ├── 2 线 Dual SPI
│   ├── 4 线 Quad SPI
│   └── 8 线 Octo SPI
│
├── 传输模式
│   ├── 命令-地址-数据 (标准)
│   ├── 连续传输 (流模式)
│   └── 内存映射 (XIP)
│
└── DMA 支持
    └── GPDMA 通道 → 高速传输
```

### NuttX 框架对接

```
NuttX MTD 框架:
  mtd_dev_s → 注册 Flash 设备
    → /dev/mtdblockN

文件系统:
  mount("/dev/mtdblock0", "/mnt/flash", "littlefs", ...)
```

### 数据流

```
XSPI 读取 (内存映射模式):
  CPU → XSPI 地址空间 → 自动发送命令
    → Flash 返回数据 → CPU 读取

XSPI 写入 (命令模式):
  应用 → MTD write()
    → XSPI 发送写命令 → Flash 编程
    → 状态轮询完成
```

## 理由

NPU 推理需要大容量模型权重（数 MB），SRAM 无法全部容纳，
内存映射模式让 NPU 可以零拷贝直接访问 Flash 中的权重数据。
DTR 模式提供最大读取带宽，减少推理时的数据搬运瓶颈。
MX25UW25645G 是 ST 官方 N6-DK 板载 Flash，驱动参考代码成熟。
